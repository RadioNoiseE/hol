General Rules:

1. Records, methods and constants: an idiomatic abbreviation or the
   full word.  If HOL Light has the operation, use its name in camel
   case and abbreviate consistently if desired.  These need no
   annotation.

2. Parameters and record components, in order of preference:
   a. a reserved name from the table below;
   b. the first letter of what the variable means;
   c. the capital letters of its type name, or the type's first
      letter;
   d. several parameters with the same role and type: the same name
      with digits appended to all of them
   e. otherwise case by case, and add the result to the table.

3. Fields: an idiomatic abbreviation or the full word.

4. Local variables, in order of preference:
  a. a reserved name from the table below;
  b. a variable that matters across several lines: an abbreviation or
     a short word for its role;
  c. a value derived from a parameter or another local: the next
     letter after that variable's letter, skipping reserved letters,
     or append digit(s);
  d. the first letter of what the variable means;
  e. the capital letters of its type name, or the type's first letter;
  f. otherwise case by case, and add the result to the table.

5. Booleans, anywhere: a short word, so conditions read naturally.

6. A collection of things named x is named xs.  This rule only
   applies when x needs to coexist with xs.

7. A reserved name may take another meaning within a structure
   (record, method or case) that does not declare a variable with its
   reserved meaning.  Qualified accessor calls do not count as uses of
   the name.

8. A pattern variable takes the record's name or, when it binds a
   component, that component's name.  These need no annotation.


Reserved Names:

f, x         -> function and argument of an application, f(x)
i, j         -> a loop index
s, t, u      -> a term
theta, sigma -> a substitution
